# SEO · AEO · GEO 수행 계획 — 백석시그니처자이 데모 사이트

## 용어
| 구분 | 목표 | 대상 |
|---|---|---|
| **SEO** (검색엔진 최적화) | 검색 결과 상위 노출과 클릭 | 구글, 네이버, 다음, 빙 |
| **AEO** (답변엔진 최적화) | 질문에 대한 "바로 답"으로 채택 | 구글 추천 스니펫·AI 개요, 네이버 지식스니펫, 음성 비서 |
| **GEO** (생성형엔진 최적화) | 생성형 AI 답변에 인용·언급 | ChatGPT 검색, Perplexity, Claude, Gemini, 구글 AI 모드 |

세 가지는 따로 노는 게 아니라 **기술 기반 → 구조화된 사실 → 질문형 콘텐츠 → 외부 신뢰 신호** 순서로 쌓인다.

## 현황 점검 결과 (착수 시점)
- 핵심 사실(타입별 면적·세대수, 평면, ※유의사항, 학교 배정 등)이 **JavaScript로만 그려져** 빌드된 HTML에 없다. AI 크롤러 대부분은 JavaScript를 실행하지 않으므로 GEO에 치명적이다.
- 사이트맵, robots.txt, canonical, 구조화 데이터(JSON-LD), 404 페이지가 없다.
- 관리자 페이지에만 noindex가 있고, `/api`에는 색인 차단이 없다.
- 페이지별 title·description은 있다(양호). 페이지마다 h1이 하나다(양호). 이미지 대체텍스트가 있다(양호).
- 인라인 편집으로 바꾼 문구는 브라우저에서만 반영되어, JavaScript를 실행하지 않는 크롤러는 바꾸기 전 원문을 본다.

## 전체 워크플로우

| 단계 | 내용 | 담당 |
|---|---|---|
| 0. 기준 정하기 | 운영 도메인, 핵심 검색어, 사실 정보(일정·견본주택 등) 확정 | **사람** |
| 1. 기술 기반 | 사이트맵, robots, canonical, OG, 404, 색인 차단, 정적 HTML | **Claude** |
| 2. 구조화된 사실 | JSON-LD(단지·타입·FAQ·경로), 사실을 텍스트와 표로 | **Claude** (사실 검수는 사람) |
| 3. 질문형 콘텐츠 | FAQ, 페이지별 요약, llms.txt | **Claude 초안 → 사람 검수** |
| 4. 등록과 측정 | 서치콘솔·서치어드바이저·빙 등록, 사이트맵 제출, 분석 도구 | **사람** (코드 연결은 Claude) |
| 5. 외부 신뢰 신호 | 네이버 플레이스·구글 비즈니스, 블로그·보도자료, 부동산 포털 | **사람** |
| 6. 모니터링·개선 | 순위, 색인 상태, AI 답변 인용 여부 정기 점검 → 콘텐츠 보강 | **사람 + Claude** |

**무엇부터:** 1단계(기술 기반)와 정적 HTML 전환이 먼저다. 크롤러가 내용을 읽지 못하면 이후 작업이 모두 효과가 없다. 그다음 2·3단계, 그리고 도메인이 정해지는 대로 4단계를 바로 진행한다.

## Claude가 직접 조치 (완료)
- [x] 현황 점검
- [x] JavaScript로 그리던 핵심 콘텐츠(면적표·평면 정보·유의사항)를 빌드 시 정적 HTML로 미리 생성
- [x] 사이트맵(`sitemap.xml`), `robots.txt`(관리자·API 차단, AI 크롤러 허용), 페이지별 canonical·og:url·og:image, 트위터 카드
- [x] 관리자·API 응답에 색인 차단 헤더(X-Robots-Tag), 404 페이지
- [x] 구조화 데이터: WebSite, ApartmentComplex(주소·세대수·편의시설), 타입별 Apartment(면적), BreadcrumbList, FAQPage
- [x] FAQ 페이지(카탈로그 사실만 근거로 질문·답변 초안)
- [x] `llms.txt`(AI용 사이트 요약과 핵심 사실, 페이지 안내)
- [x] 운영 주소는 환경변수(`SITE_URL`)로 받는다. 없으면 Vercel 운영 도메인 → 로컬 주소 순으로 쓴다.
- [x] 검증: 빌드 결과에서 JavaScript 없이 핵심 사실이 보이는지, JSON-LD 문법, 사이트맵·robots 내용

## 사람이 직접 해야 하는 것
| 할 일 | 이유 / 필요한 것 |
|---|---|
| 운영 도메인 확정과 Vercel 연결, `SITE_URL` 환경변수 등록 | 사이트맵·canonical의 기준 주소 |
| **사실 정보 확정**: 분양 일정, 분양가(공개 시), 견본주택 주소·전화·운영시간 | 카탈로그에 없어 만들 수 없다. 확정되면 FAQ·구조화 데이터에 넣는다 |
| FAQ 답변 검수와 분양 광고 표시 규정 검토 | 표시·광고 관련 법적 책임은 분양 주체에 있다 |
| 구글 서치콘솔, **네이버 서치어드바이저**, 빙 웹마스터 도구 소유 확인과 사이트맵 제출 | 계정 로그인이 필요하다. 확인 코드를 주면 Claude가 메타태그로 넣는다 |
| GA4 / 네이버 애널리틱스 계정 생성 | 추적 ID를 주면 Claude가 연결한다 |
| AI 크롤러 허용 정책 최종 결정 | 기본값은 '허용'(홍보 사이트라 인용될수록 유리). 막으려면 robots에서 바꾼다 |
| 네이버 플레이스·구글 비즈니스 프로필에 견본주택 등록 | 지역 검색과 AI 답변의 위치 정보 근거 |
| 외부 채널: 네이버 블로그·카페, 보도자료, 부동산 포털(네이버 부동산 등) 정보 정합성 | 외부 언급과 링크가 생성형 AI의 신뢰 근거가 된다 |
| 정기 점검: 검색 순위, 색인 상태, "백석시그니처자이" 질문에 AI가 어떻게 답하는지 | 결과를 주면 Claude가 콘텐츠를 보강한다 |

## 결정이 필요한 사항
- **인라인 편집 내용의 색인 반영**: 지금은 편집한 문구가 브라우저에서만 바뀐다. 검색·AI에 바뀐 문구까지 반영하려면 빌드할 때 DB의 편집 내용을 HTML에 넣고, 저장할 때 Vercel 재배포를 실행하도록(Deploy Hook) 연결해야 한다. Deploy Hook 생성은 사람이, 연결 코드는 Claude가 한다.

## 구현 위치 (Claude 조치 결과)
| 항목 | 위치 |
|---|---|
| 사실 정보·페이지 목록·FAQ (단일 출처) | `frontend/src/data/site.js` |
| 정적 HTML 생성·메타·JSON-LD·sitemap/robots/llms.txt | `frontend/build/seo-plugin.js` (Vite 플러그인) |
| HTML 문자열 렌더러 (빌드·브라우저 공용) | `frontend/src/js/render.js` |
| FAQ 페이지 / 404 페이지 | `frontend/faq.html`, `frontend/404.html` |
| 색인 차단 헤더 | `vercel.json`(admin·api·404), `backend/src/app.js`(API) |

- 사실 정보가 바뀌면 `site.js`만 고치면 FAQ 화면, 구조화 데이터, llms.txt가 함께 바뀐다.
- FAQ 문구는 인라인 편집 대상이 아니다. 구조화 데이터와 화면이 어긋나지 않도록 `site.js`에서만 고친다.
- 검증 결과: JavaScript 없이도 면적표·평면 정보·유의사항(약 670개 항목)·FAQ가 HTML에 들어 있다. 모든 페이지의 JSON-LD 문법이 맞고, 관리자·404는 noindex다.

## 검색 노출 스위치 (데모 운영 중)
- 이 데모는 검색에 노출하지 않는다. 검색엔진 등록을 하지 않아도 막지 않으면 색인될 수 있으므로 **기본값을 차단**으로 했다(환경변수 없이 적용).
  - 모든 페이지 `noindex, nofollow`, AI 크롤러(GPTBot·ClaudeBot·PerplexityBot 등) robots 차단, `sitemap.xml`·`llms.txt` 미생성
  - 검색엔진 크롤러는 robots에서 막지 않는다. 막으면 noindex를 읽지 못해 주소만 검색에 남을 수 있다.
- 구글 서치콘솔: 소유 확인 파일(`frontend/public/google3c43749f423008fc.html`)은 유지하고, 사이트맵은 제출하지 않는다. 사이트 전체 '일시적 URL 삭제' 요청은 noindex가 반영될 때까지의 임시 조치다.
- 네이버·빙 등록은 공개 시점까지 보류한다.
- 정식 공개 시: `SEARCH_INDEXING=on` → 재배포 → 서치콘솔 삭제 요청 취소 → 사이트맵 제출 → 네이버·빙 등록.
- 서치콘솔 정리 순서: 차단 배포 → 삭제 요청 처리 완료와 URL 검사 결과(미등록 또는 noindex 제외) 확인 → 속성 삭제 → 확인 파일 삭제 후 배포.
