# 분양사이트 3단계 — 사이트 콘텐츠 운영

개발자 없이 관리자가 사이트 내용을 직접 바꾸는 도구를 만든다. 마케팅 운영이 목적이라 편의성과 화면 연출이 중요하다.
이 단계가 끝나면 확인과 보고를 마친 뒤 멈춘다.

## 시작 전 확인
1. **공통 규칙**: 프로젝트 루트 `CLAUDE.md`에 "분양사이트 프로젝트 공통 기반"이 있는지 본다. 없으면 진행하지 말고 "홍보 사이트 구축(presale-1-site)부터 진행해 주세요"라고 알린다.
2. **관리자 로그인**: `/api/auth/login`, `/api/auth/me`와 관리자 화면(`admin.html`)이 있는지 본다. 없으면 진행하지 말고 "분양 접수 운영(presale-2-intake)을 먼저 진행해 주세요"라고 알린다. 편집기와 팝업 관리는 이 로그인 위에 얹힌다.
3. **편집 대상 표시**: 1단계에서 화면 요소에 `data-edit`, 배경 이미지 영역에 `data-edit-bg`를 달아 두었는지 본다. 빠진 곳이 있으면 이 단계에서 보완한다.
4. **이미 진행된 상태인지**: 편집기나 팝업이 이미 있으면 새로 만들지 말고 아래 지시사항 중 빠진 것만 보완한다.
5. 묻지 않고 진행한다. 팝업 노출 방식 기본값은 개별 팝업이다.

## 이 단계의 지시사항
아래는 사용자가 직접 정한 지시사항이다. 하나도 빠뜨리지 않는다.

**인라인 편집**
* 사용자 화면에서 버튼이든 문장이든 비주얼이든 그 자리에서 바로 편집하고 저장할 수 있게 해줘.
* 관리자만 쓸 수 있고, 방문자에게는 편집 코드가 아예 로드되지 않아야 해.
* 로그아웃하면 편집 바가 사라져야 해.
* 편집 바의 편집 종료 버튼은 호버 상태도 제대로 보이게 해줘.

**메인 팝업**
* 메인에 팝업을 추가해줘.
* 팝업이 여러 개일 때 슬라이드로 보여줄지 따로따로 보여줄지 관리자가 고를 수 있게 해줘. 기본값은 개별 팝업이야.
* 팝업은 이벤트 팝업과 긴급공지 팝업 두 개를 넣어줘.
* 팝업이 떴을 때는 포커스가 안 보이는 상태로 시작하게 해줘. 분양사이트라서 처음부터 포커스가 보이는 건 과해.

## 진행 순서
1. **요구사항 문서**: 이 단계 지시사항을 `doc/03-content-prompt.md`로 남긴다.
2. **인라인 편집**: `references/inline-editor.md` 기준. 참고 구현은 `assets/content.js`, `assets/editor.js`, `assets/editor.css`. 이 사이트의 쿠키명·클래스명에 맞게 고쳐 쓴다.
3. **메인 팝업**: `references/main-popup.md` 기준. 참고 구현은 `assets/popup.js`, `assets/popup.css`. 서버 테이블·API와 관리자 '팝업 관리' 탭을 함께 만든다.
4. **확인** (아래 완료 기준)
5. **문서**: README(인라인 편집·메인 팝업 설명, API 표)와 `doc/design-system.md`(팝업 컴포넌트, 포커스 원칙)를 갱신한다.
6. **커밋**: 이 단계 커밋으로 남긴다. 푸시는 사용자가 요청할 때만 한다.

## 완료 기준
**인라인 편집**
- [ ] 방문자로 접속하면 편집기 파일 요청이 0건이고 `/api/auth/me` 요청도 없다(네트워크 리소스 목록으로 확인).
- [ ] 관리자로 접속하면 편집 바가 뜨고, 텍스트·버튼(문구·링크)·이미지(주소·업로드)·배경 이미지를 고쳐 저장할 수 있다.
- [ ] 저장한 내용이 로그아웃한 방문자 화면에 그대로 보인다.
- [ ] `<img onerror>`, `<script>`, `javascript:` 링크가 저장·렌더 과정에서 무력화된다.
- [ ] 로그아웃하면 편집 바와 편집 상태가 즉시 사라진다.
- [ ] '편집 종료' 버튼에 마우스를 올려도 글자가 읽힌다(실제 hover로 배경·글자색 확인).

**메인 팝업**
- [ ] 첫 실행 시 이벤트·긴급공지 팝업 2개가 생기고, 기본 노출 방식은 개별이다.
- [ ] 개별: 나란히 뜨고(모바일은 세로), '오늘 하루 보지 않기'한 팝업만 새로고침 후 사라지며, Esc와 마지막 닫기에서 레이어와 스크롤 잠금이 풀린다.
- [ ] 관리자에서 슬라이드로 바꾸면 메인이 슬라이드로 바뀌고, 넘김·점·자동 넘김이 동작한다.
- [ ] 팝업이 열린 직후 어떤 요소에도 포커스 링이 보이지 않는다. Tab을 누르면 포인트 컬러 포커스가 보이고, Tab/Shift+Tab이 팝업 안에서 순환한다.
- [ ] 관리자에서 추가·수정·노출 끄기·삭제가 되고, 노출을 끄거나 시작일이 미래인 팝업은 메인에 나오지 않는다.
- [ ] 위험한 링크, 앞뒤 바뀐 기간, 잘못된 노출 방식은 서버가 거부한다.
- [ ] 테스트로 만든 팝업은 지우고, 노출 방식은 기본값(개별)으로 되돌렸다. 테스트 세션은 정리했다.

## 마무리 보고 (한국어)
- 인라인 편집 사용법(관리자 로그인 → 사이트 화면 편집 → 저장)
- 팝업 관리 사용법과 기본 팝업 2개의 내용(실제 이벤트가 정해지면 관리자가 문구를 바꾸라고 안내)
- 확인한 항목과 확인하지 못한 항목
- 세 단계가 모두 끝났음을 알린다. 이후 기능 추가는 성격에 따라 접수 운영(예: 상담 예약) 또는 콘텐츠 운영(예: 갤러리·뉴스) 묶음으로 분류해 진행한다고 안내한다.
