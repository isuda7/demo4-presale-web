# 분양사이트 2단계 — 분양 접수 운영

고객 정보를 받고 관리하는 기능을 만든다. 분양사의 영업 데이터를 다루므로 보안과 정확성이 우선이다.
이 단계가 끝나면 확인과 보고를 마친 뒤 멈춘다.

## 시작 전 확인
1. **공통 규칙**: 프로젝트 루트 `CLAUDE.md`에 "분양사이트 프로젝트 공통 기반"이 있는지 본다. 없으면 1단계가 진행되지 않은 것이니, 진행하지 말고 "홍보 사이트 구축(presale-1-site)부터 진행해 주세요"라고 알린다.
2. **홍보 사이트**: `frontend/`에 메뉴 페이지와 partials, 디자인 시스템이 있는지 본다. 없으면 위와 같이 안내하고 멈춘다.
3. **이미 진행된 상태인지**: 신청 화면이나 관리자 API가 이미 있으면 새로 만들지 말고 아래 지시사항 중 빠진 것만 보완한다.
4. 묻지 않고 진행한다. 상태 값, 신청 항목, 타입 목록은 아래 기준과 카탈로그 데이터로 정한다.

## 이 단계의 지시사항
아래는 사용자가 직접 정한 지시사항이다. 하나도 빠뜨리지 않는다.

**분양 신청**
* 분양 신청 화면을 추가하고, 디자인 시스템과 관리자 기능을 적용해줘.
* 신청을 마감하는 스위치도 둬줘. 마감하면 화면에는 안내만 보이고 서버도 신청을 거부해야 해.

**관리자**
* 관리자 모드는 비밀번호로 로그인하게 해줘.
* 신청 목록을 보고, 검색·상태·기간으로 조회하고, 삭제하고, CSV로 내려받을 수 있어야 해.
* 목록 화면의 검색, 상태, 타입, 신청기간, 조회, 초기화는 한 줄에 놓아줘.

## 진행 순서
1. **요구사항 문서**: 이 단계 지시사항을 `doc/02-intake-prompt.md`로 남긴다.
2. **백엔드**: 스키마, 신청 API, 인증, 관리자 API — `references/intake-implementation.md`와 `assets/`의 참고 구현을 따른다.
3. **신청 화면**: `apply.html` — 헤더·푸터 partial과 디자인 시스템을 그대로 쓴다. 홍보 사이트의 "관심고객 등록" 버튼과 평면 타입의 "이 타입 관심등록" 링크를 이 화면으로 연결한다.
4. **관리자 화면**: `admin.html` — 로그인, 현황, 마감 설정, 한 줄 조회 조건, 목록, CSV.
5. **확인** (아래 완료 기준)
6. **README**: 기능 요약, API 표, 환경변수(`ADMIN_PASSWORD`, `ADMIN_TOKEN_SECRET`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`)를 갱신한다.
7. **커밋**: 이 단계 커밋으로 남긴다. 푸시는 사용자가 요청할 때만 한다.

## 완료 기준
- [ ] 신청: 빈 제출 시 필드별 오류, 정상 제출 시 완료 화면, 같은 번호 재신청 409, 잘못된 값은 서버에서도 400
- [ ] 마감: 스위치를 켜면 신청 화면에 폼 없이 안내만 보이고, API로 직접 보내도 403
- [ ] 관리자: 잘못된 비밀번호 거부, 미로그인 시 관리자 API 401, 로그아웃 후 재사용 불가
- [ ] 조회: 검색(이름·연락처), 상태, 타입, 기간, 빠른 기간이 각각 결과를 바꾼다
- [ ] 1440px에서 검색·상태·타입·신청기간·조회·초기화가 한 줄이고 입력칸 아래선이 맞는다
- [ ] 상태 변경·메모 저장·개별/일괄 삭제가 된다
- [ ] CSV가 BOM으로 시작하고, 현재 필터가 반영되고, `=`로 시작하는 값이 무력화된다
- [ ] 저장소에 비밀값 없음. 테스트 중 비밀번호 값을 출력하지 않았고, 테스트 세션은 정리했다.
- [ ] 테스트로 바꾼 상태(마감 스위치 등)는 원래대로 돌려놓았다.
