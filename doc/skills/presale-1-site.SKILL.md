# 분양사이트 1단계 — 홍보 사이트 구축

방문자가 보는 화면을 만든다. 카탈로그를 웹으로 옮기는 일이다.
이 단계가 끝나면 로컬에서 돌아가고 배포 가능한 홍보 사이트가 있어야 하고, 확인과 보고를 마친 뒤 멈춘다.

## 시작 전 확인
1. **카탈로그 파일**: 요청에 PDF 경로가 없으면 묻는다. 다른 것은 묻지 않고 기본값으로 진행한다.
2. **공통 규칙**: 프로젝트 루트에 `CLAUDE.md`가 없거나 "분양사이트 프로젝트 공통 기반" 내용이 없으면 `assets/CLAUDE.md`를 루트에 복사한다. 이미 다른 CLAUDE.md가 있으면 내용을 덮어쓰지 말고 아래에 덧붙인다. 이후 모든 작업은 이 규칙을 따른다.
3. **이미 진행된 상태인지**: `frontend/`에 메뉴 페이지가 이미 있으면 처음부터 다시 만들지 말고, 무엇이 빠졌는지 확인해 보완한다.

## 이 단계의 지시사항
아래는 사용자가 직접 정한 지시사항이다. 하나도 빠뜨리지 않는다.

**디자인 시스템 / 콘텐츠**
* 카탈로그의 스타일과 컨셉으로 디자인 시스템을 만들어서 분양사이트에 반영해줘.
* 카탈로그 콘텐츠는 빠짐없이 전부 넣어줘.
* 새로 추가하는 화면에도 같은 디자인 시스템을 적용해.

**사이트 구조**
* 원페이지 방식 말고 메뉴별 페이지 방식으로 나눠줘.
* 내비게이션이 중복으로 들어가 있으면 헤더 것만 쓰도록 정리해줘.

**성능**
* 페이지를 열 때 CSS가 적용되지 않은 화면이 잠깐 보이는 일이 없게 해줘.

**연출**
* 헤더 기본 상태에는 배경 블러를 적용해줘.
* 비주얼 영역에 AOS(스크롤 등장 효과)를 적용해줘. 범위는 사이트 전체 공통이야.
* 접근성 포커스 스타일은 가독성은 유지하되 사이트 컨셉에 맞게 자연스럽게 처리해줘.

## 진행 순서
1. **요구사항 문서**: 공통 기반 + 이 단계 지시사항을 정리해 `doc/prompt.md`(또는 `doc/01-site-prompt.md`)로 남긴다.
2. **프로젝트 기반**: `frontend/`·`backend/`·`api/` 구조, `package.json` 스크립트(dev/build/preview/db:migrate), `vercel.json`, `.env.example`, `.gitignore`(.env, backend/data, dist)를 만든다. 비밀값은 `openssl rand`로 만들어 로컬 `.env`에만 넣고 값은 출력하지 않는다. 참고 구현: `assets/`(vite.config.js, vercel.json, api-index.js, db.js, env.example).
3. **카탈로그 분석**: `references/catalog-analysis.md` 순서대로 텍스트·서체·색·레이아웃 문법·사진·도면을 뽑는다. 스크립트는 `scripts/`에 있다.
4. **디자인 시스템**: 토큰(CSS 변수)과 컴포넌트를 만들고 `doc/design-system.md`에 남긴다.
5. **페이지 퍼블리싱**: `references/frontend-structure.md` 기준으로 메인 + 메뉴별 페이지를 만들고 카탈로그 전 콘텐츠를 넣는다. 공통 부분은 partials로 만든다.
6. **연출**: 헤더 블러, AOS(`assets/aos-setup.html`을 이 사이트의 클래스명에 맞게 선택자만 고쳐 사용), 포커스 스타일.
7. **확인** (아래 완료 기준)
8. **README**: 로컬 실행 방법, 환경변수 이름, Turso·Vercel 배포 절차, 페이지 구성, AOS 설정 위치를 쓴다.
9. **커밋**: 기본 브랜치에 커밋 이력이 없으면 첫 커밋으로, 있으면 이 단계 커밋으로 남긴다. 푸시는 사용자가 요청할 때만 한다.

## 완료 기준 (브라우저로 직접 확인)
- [ ] 카탈로그 페이지별 체크리스트의 모든 항목(제목·본문·리스트·이미지·※유의사항)이 어느 메뉴 페이지엔가 있다.
- [ ] 모든 페이지가 빌드되고, 1440px·375px에서 가로 넘침이 없고, 깨진 이미지가 없다.
- [ ] 각 페이지에 h1이 하나 있고, 헤더에 현재 메뉴가 표시되며, 서브내비가 중복으로 없다.
- [ ] 개발 서버와 빌드(`vite preview`) 모두에서 CSS가 첫 페인트 전에 로드된다(렌더 블로킹 확인).
- [ ] 헤더 기본 상태에 블러가 있고, 모바일 메뉴가 여전히 전체화면으로 열린다.
- [ ] AOS 대상이 끝까지 스크롤했을 때 모두 나타나고(숨은 채 남는 요소 없음), 첫 화면은 로드 시 나타난다.
- [ ] 키보드 Tab 이동 시 포인트 컬러 포커스가 보이고, 마우스 클릭에는 링이 생기지 않는다.
- [ ] 저장소 어디에도 비밀값이 없다(.env 값으로 검색해 0건).

## 마무리 보고 (한국어)

- 카탈로그에 있었지만 웹에서 다르게 처리한 것(예: 텍스트 레이어가 깨진 페이지를 직접 옮겨 적음)
