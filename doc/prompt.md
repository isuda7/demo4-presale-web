# 분양사이트 제작 프롬프트

## 역할
너는 분양사이트 제작 경력 30년의 베테랑 크리에이티브 디자이너이자 풀스택 개발자다.
카탈로그의 톤앤매너를 웹으로 옮기는 감각과, 바로 운영할 수 있는 수준의 구현력을 함께 발휘한다.

## 목표
첨부한 분양 카탈로그 PDF(`260604_백석시그니처자이_카탈로그_시안.pdf`)를 바탕으로 분양 홍보 사이트를 만든다.
구성은 사용자 화면, 분양 신청, 관리자, 인라인 편집이다.
로컬에서 실제 배포와 같은 환경으로 실행되는 것을 확인하고, **환경변수만 넣고 푸시하면 배포되는 상태**로 넘긴다.

## 기술 스택 (변경 금지)
| 구분 | 사용 기술 |
|---|---|
| 코드 저장소 | GitHub |
| 실행·배포 | Vercel: 프론트 빌드와 백엔드(Hono) 실행, 푸시하면 자동 빌드·배포 |
| 데이터베이스 | Turso(libSQL): 신청 데이터와 편집 콘텐츠, 설정 저장 |
| 프론트엔드 | 순수 HTML/CSS/JS, Vite 멀티페이지 빌드 |
| 백엔드 | Hono (Vercel Functions로 실행) |

## 폴더 구조
- `frontend/`와 `backend/`로 나눠서 설계한다.
- `frontend/`: Vite 멀티페이지(메인, 신청, 관리자 등), 디자인시스템 CSS, 정적 에셋
- `backend/`: Hono 앱, 라우트, DB 접근, 인증, 마이그레이션·시드 스크립트
- 루트: `vercel.json`, `.env.example`(변수 이름만 적고 값은 비움), `README.md`

## 보안 원칙 (필수)
- 관리자 비밀번호와 토큰 서명용 비밀값은 **코드·문서·커밋 어디에도 적지 않는다.** 환경변수로만 다룬다.
- `.env*`는 `.gitignore`에 넣는다. `.env.example`에는 변수 이름만 적는다.
- 관리자 API는 모두 서버에서 토큰을 검증한다. 화면을 숨기는 것만으로 권한을 처리하지 않는다.
- 로그인 시도 횟수를 제한하고, 토큰에는 만료 시간을 둔다.

## 세부 요구사항

### 1. 디자인시스템과 콘텐츠
- 카탈로그를 분석해서 컬러, 타이포그래피, 여백, 그리드, 장식 요소, 사진 톤을 **디자인 토큰(CSS 변수)**으로 정의한다.
- 버튼, 카드, 섹션 헤더, 표, 폼, 배지, 모달 같은 공통 컴포넌트를 만든다.
- **카탈로그의 모든 콘텐츠를 빠짐없이 옮긴다.** 텍스트, 이미지, 평면도, 면적표, 유의사항(※ 문구)이 모두 포함된다.
  이미지는 PDF에서 추출하고 웹에 맞게 최적화한다.
- 반응형(PC·태블릿·모바일)과 기본 접근성(대체텍스트, 키보드 조작, 명도 대비)을 지킨다.

### 2. 분양 신청 화면
- 별도 페이지로 만들고 디자인시스템을 그대로 적용한다.
- 입력 항목: 이름, 연락처, 관심 타입, 방문 희망일, 문의 내용, 개인정보 수집·이용 동의
- 클라이언트와 서버 양쪽에서 입력값을 검증하고, 중복 제출을 막고, 완료 안내를 보여준다.

### 3. 관리자 모드
- 비밀번호로 로그인하고 로그아웃할 수 있다.
- 신청 목록을 페이지 단위로 보여준다.
- 조회 조건: **검색**(이름·연락처), **상태**(예: 신규, 연락완료, 계약, 보류), **기간**(신청일 시작~종료). 조건은 함께 쓸 수 있다.
- 관리자가 신청 건의 상태를 바꿀 수 있다.
- 한 건씩 또는 여러 건을 골라 삭제한다. 삭제 전에 확인을 받는다.
- 현재 조회 조건이 적용된 목록을 **CSV로 내려받는다.** 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM을 붙인다.

### 4. 신청 마감 스위치
- 관리자 화면에서 켜고 끈다. 값은 DB에 저장한다.
- 마감 상태에서는 신청 화면에 **안내 문구만** 보이고 폼은 렌더링하지 않는다.
- 서버도 신청 API 요청을 **거부한다.** 마감 상태임을 알 수 있는 응답 코드와 메시지를 보낸다.

### 5. 사용자 화면 인라인 편집
- 관리자는 사용자 화면에서 **텍스트, 버튼(문구·링크), 비주얼(이미지)**을 그 자리에서 바로 편집하고 저장한다.
- 편집할 수 있는 영역에는 고유 키(예: `data-edit-key`)를 붙인다. 저장한 값은 DB에 두고 페이지를 불러올 때 반영한다.
- **방문자에게는 편집 코드(JS/CSS)를 아예 불러오지 않는다.** 관리자 세션이 확인될 때만 동적으로 로드한다.
- 편집 모드에서는 상단에 편집 바(편집 켜기·끄기, 저장, 취소, 로그아웃)를 띄운다.
- **로그아웃하면 편집 바와 편집 상태가 바로 사라진다.**
- 저장 API는 관리자 토큰을 검증한다.

## 로컬 실행
- 로컬에서도 Turso와 호환되는 DB(로컬 libSQL 파일 또는 `turso dev`)로 같은 코드가 돌아가게 한다.
- 명령 하나(예: `npm run dev`)로 프론트와 백엔드를 함께 띄운다. 마이그레이션·시드 스크립트도 준비한다.
- 브라우저에서 직접 확인한다: 신청 → 관리자 조회·필터·상태 변경·삭제·CSV → 마감 스위치 → 인라인 편집 → 로그아웃 후 편집 바 사라짐.
